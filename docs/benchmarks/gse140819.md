# GSE140819 QC benchmark

Local input: `data/gse140819` (ignored by Git). The inventory beside this document
records matrix dimensions, metadata coverage, reference flag counts, and metadata
SHA-256 hashes. It contains aggregate information, not expression matrices.

## Observed input audit

The local extraction contains 40 matrix/metadata pairs and 216,490 metadata rows.
All metadata identifiers are unique within their preparation. The `emptydrop`
column is absent in 23 preparations; those cannot enter empty-droplet agreement
calculations as though they had negative labels.

The initial delimiter-based audit incorrectly reported missing sequences for
`HTAPP-951-SMP-4652_TST-V2`: its identifiers use an underscore before the sequence,
where other preparations use a hyphen. All 3,992 sequences are present. Sixteen
preparations require handling naming differences explicitly. The source-aware audit now passes for all 40 preparations: every metadata
sequence matches uniquely within its corresponding matrix, every explicit channel
agrees with the archive, and all extracted metadata files match the archived
bytes. These findings do not establish missing expression data.

Reproduce the source-aware audit with:

```bash
python scripts/audit_gse140819.py --output docs/benchmarks/gse140819-inventory.csv
```

See [the complete inventory](gse140819-inventory.csv). The audit verifies extracted
metadata against archive bytes and checks barcode membership; it does not yet
verify complete extracted matrix bytes or biological specimen pairings.

## What the labels establish

The [study methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC7220853/) describe
EmptyDrops predictions of empty droplets, Scrublet predictions of doublets
(expected doublet rate 0.06), and SoupX estimates of ambient RNA. Predicted
doublets and empty droplets were flagged and retained for analysis.

Consequently, `doublet` and `emptydrop` are computational reference calls, not
independent experimental truth. Agreement with these calls must not be presented
as measured biological accuracy, particularly when evaluating the same methods.
`annotate` provides published cell annotations for retention analyses. It does not
establish that every annotated barcode is healthy or that every rare annotation
is correct. No per-cell ambient RNA truth was established by this inventory.

## Inventory and barcode join

Each CSV basename must match one local HDF5 basename and one archive metadata
member. The original GEO accession and channel come from archive filenames; the
matching archive matrix must share both. Extracted metadata must equal the
archived metadata byte for byte.

Read matrix `shape` and `barcodes` from the legacy genome group or modern `matrix`
group without loading expression values. Metadata identifiers end in either
`-SEQUENCE` or `_SEQUENCE`. Validate any explicit metadata channel against the archive (some identifiers
omit it),
then join sequences only within that preparation, requiring uniqueness in both
metadata and matrix and complete metadata sequence coverage. Matrix barcode
suffixes are local channel identifiers: CY112 uses `-1` although its original
archive and metadata channel is 2. Never join bare sequences across preparations.

The inventory counts `TRUE` flags only after checking that present flag columns
contain exclusively `TRUE` or `FALSE`. A blank flag-count field means the column
was absent, not zero positives. Barcodes outside the metadata remain unlabeled;
they must not become negative examples or automatically be designated empty.

## Baseline evaluation contract

### Verified comparison set

The [paired preparation manifest](gse140819-paired-preparations.csv) records nine
preparations across four specimens explicitly compared in the study: HTAPP-656,
HTAPP-963, CLL1, and O-PDX1. Figure 1b identifies specimen/protocol combinations;
Figure 6 and Extended Data Figure 10 establish the matched cell/nucleus comparisons.
HTAPP-963 additionally has a CST nucleus preparation (Figure 5). Treat these as
four specimen groups, not five independent pairs when comparing two nucleus
protocols against the same breast-cancer cell preparation. These are matched
specimens, not measurements of the same individual cells.

The [GEO sample table](gse140819-geo-samples.csv) preserves titles, source tissue
descriptions, and sample-type fields for all 40 accessions. It was retrieved from
the GEO series SOFT response on 2026-09-10; its source hash is recorded in each row.
Retrieve that response with:

```bash
curl --fail --location 'https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE140819&targ=gsm&form=text&view=full' -o data/gse140819/GSE140819-family.soft.txt
```

Pairing and protocol interpretation were checked against the
[study PDF hosted by Harvard](https://ccsp.hms.harvard.edu/wp-content/uploads/2020/12/Slyper-2020-NatMed.pdf).
GEO's generic extraction text alone does not distinguish assays. The CLL `fresh`
filename denotes the cell preparation, but the paper describes thawed cells;
do not interpret that suffix as a verified preservation condition. Donor identity
and chemistry are not inferred from specimen IDs or generic GEO protocol text.

### Evaluation requirements

- Run each preparation independently for sample-specific QC. Keep source matrices
  immutable and published labels out of the fitting inputs.
- Verify assay, specimen, donor, protocol, and chemistry from study metadata before
  assigning comparison groups. Similar filenames alone do not establish pairing.
- Report retention by sample and published cell annotation, with counts and
  denominators. Include rare annotations and reference-flagged cells separately.
- Report doublet/empty-droplet reference agreement separately from independent
  accuracy. Stratify cells and nuclei rather than demanding identical proportions.
- Record configuration, software versions, CPU/GPU backend, runtime, memory, and
  failures with every baseline. Hold specimens out when selecting QC defaults.
- Supplement this study with independent experimental labels and controlled
  perturbations before claiming improved doublet, damage, or ambient RNA accuracy.

## First CLL baseline

Both CLL preparations completed QC through the public pipeline API on CPU. This
run selected the published metadata barcodes from raw matrices and supplied only
sample identity and counts to QC. Published annotations and flags were joined
after execution. It evaluates retention within a previously selected population,
not raw-droplet recovery. Gene symbols were made unique with AnnData's standard
suffixing; original gene IDs remain in the input feature table.

| Preparation | Input/retained | Core | Borderline | Quarantine | Fits manifold |
| --- | ---: | ---: | ---: | ---: | ---: |
| Cells | 2,562/2,562 | 2,447 | 113 | 2 | 2,435 |
| Nuclei | 2,339/2,339 | 2,253 | 86 | 0 | 2,242 |

Core state alone does not grant fitting permission: probable doublets can remain
core while being excluded from fitting. Of the published macrophage annotations,
50/54 cells and 37/42 nuclei retained manifold-fitting permission. These counts
are retention measurements, not proof of rare-cell accuracy.

Scrublet called 13 cell doublets (eight overlapping 109 reference flags) and two
nucleus doublets (one overlapping 38 reference flags). This substantial
disagreement needs investigation of preprocessing, versions, and thresholds;
neither set of predictions is independent experimental truth.

The run used seed 7, default QC settings except explicit Scrublet selection,
disabled figure writing, and `graded.nuclear_axis_applicable: false` for nuclei.
R and all stages other than QC were disabled. miQC and SampleQC were disabled by
their defaults; ambient correction was not run. This is a baseline of that
configuration, not validation of those methods or the full pipeline.

Subsequent adapter inspection found that doublet detection hard-coded seed zero,
ignoring the run seed. The initial baseline above therefore used detector seed
zero despite run seed seven. The adapter now receives the pipeline context seed
for both Scrublet and scDblFinder, including per-sample execution, and records it
in the detector metrics. Preserve these initial results as pre-fix evidence;
seed-corrected runs use separate output directories.

Both corrected CLL runs completed and recorded detector seed seven. Calls changed
from 13 to 15 for cells and from two to six for nuclei. Initial damage states
were unchanged, while manifold-fitting permissions changed for 14 cells and 21
nuclei. See [the seed comparison](gse140819-cll-seed-comparison.csv). The change
does not establish improved accuracy or explain the full reference disagreement.

Saved evidence:

- [Retention by published annotation](gse140819-cll-retention.csv)
- [Cell QC configuration](CLL-pilot1_fresh-qc-config.json) and
  [nucleus QC configuration](CLL-pilot1_TST-qc-config.json)

QC stage durations were approximately 28 and 23 seconds. Process peak RSS was
approximately 2 GiB in each run, including imports and input preparation; these
are not isolated QC memory measurements. Local inputs, configs, logs, decisions,
and execution records are under `data/gse140819/baseline/`. The runs used the
development checkout, not a freshly installed locked environment. Generalized
benchmark execution, the remaining seven matched preparations, raw-droplet
evaluation, and independent accuracy benchmarks remain outstanding.

## Corrected scDblFinder baseline

Both CLL preparations also completed the R-backed QC path (scDblFinder 1.22.0) with seed seven and
expected doublet rate 0.06. Every input cell was scored; detector warnings were
empty. Configuration otherwise matched the initial run, including disabling the
nuclear-integrity axis for nuclei. No reference labels were supplied to fitting.

| Preparation | Doublet calls | Overlap with reference flags | Fits manifold |
| --- | ---: | ---: | ---: |
| Cells | 165 | 24 of 109 | 2,286 of 2,562 |
| Nuclei | 215 | 12 of 38 | 2,039 of 2,339 |

See [detector results](gse140819-cll-scdblfinder.csv) and
[annotation retention](gse140819-cll-scdblfinder-retention.csv). These calls differ
substantially from both Scrublet runs and published flags. Agreement alone cannot
choose the better method. The configured expected rate is not a fixed quota;
the nucleus call fraction exceeds 6%. Benchmark default calibration and rare
population effects before claiming a generalizable automatic policy.

Full local provenance and resolved configurations are in each preparation's
`run_scdblfinder_v2` directory. An initial attempt with an Rscript-only custom
registry failed in planning before QC: the planner assumed an rpy2 registration.
That assumption is now fixed and regression-tested for missing optional R/GPU
backends. The completed benchmark used the standard registry.

## Engineering and figures

Implement reusable benchmark logic with one owner and a thin entry point; avoid
another collection of overlapping study scripts. QC should remain readable from
its stage entry point through validation, evidence, decisions, and artifacts.
Rendering should consume saved evaluation results through the shared figure
system. Use the Mehrara figure collection as the visual reference, including
paired donor displays only after pairings are verified. Installation, GPU support,
recovery, scale testing, and eventual workstation UI remain package-wide goals.
